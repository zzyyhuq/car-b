## 四、实现步骤（按实际开发顺序）

### 第 1 步：Maven 工程

- 单模块工程，`spring-boot-starter-parent 3.5.16` 作为 parent
- **为什么不做父子工程**：整个项目只有一个 Java 模块；小程序和 Vue 不走 Maven，拆多模块只会增加答辩解释成本
- 生成 Maven Wrapper，保证换电脑也能一条命令构建

依赖清单：
`spring-boot-starter-web`、`validation`、`data-redis`、`spring-security-crypto`、`mybatis-plus-spring-boot3-starter`、`mybatis-plus-jsqlparser`、`mysql-connector-j`、`jjwt-api/impl/jackson`、`lombok`、`spring-boot-starter-test`

### 第 2 步：统一响应与异常

- `Result<T>`：`{ code, message, data }`，`code=200` 成功
- `PageResult<T>`：`{ total, page, size, records }`
- `BusinessException`：带 code，401/403/404/400 等
- `GlobalExceptionHandler`：
  - 业务异常 → 原 code 和 message
  - 参数校验失败 → 400 + 第一条错误
  - 其它异常 → 500「系统繁忙」，同时打印日志

### 第 3 步：MyBatis-Plus 配置

- 分页插件 `PaginationInnerInterceptor(DbType.MYSQL)`
- `MyMetaObjectHandler` 自动填 `createTime / updateTime`
- 实体主键 `IdType.AUTO`，字段驼峰自动映射
- **注意**：3.5.9 之后分页必须额外引入 `mybatis-plus-jsqlparser`，否则分页不生效

### 第 4 步：JWT 鉴权

| 类 | 职责 |
|---|---|
| `JwtUtil` | 用 HS256 生成 token，载荷含 userId、role；默认 7 天过期 |
| `JwtInterceptor` | 读 `Authorization: Bearer xxx`，解析后放 `UserContext` |
| `UserContext` | ThreadLocal 存当前登录用户，请求结束清理 |
| `RequireRole` | 自定义注解，标在接口上限制角色 |
| `WebMvcConfig` | 拦截 `/api/**`，放行 `/api/auth/**`；配置 CORS；注册 BCrypt Bean |

**实现要点**
- 拦截器只做认证 + 注解角色校验，不用 Spring Security 的 `@PreAuthorize`，避免答辩被追问复杂权限模型
- 先做角色校验，再设置 `UserContext`：`preHandle` 抛异常时 `afterCompletion` 不会执行，顺序反了会导致 ThreadLocal 泄漏
- CORS 预检 OPTIONS 请求不带 token，拦截器直接放行

### 第 5 步：用户模块

- `SysUser` 实体对应 `sys_user` 表，`password` 加 `@JsonIgnore` 防止返回前端
- 接口：
  - `GET /api/user/profile`
  - `PUT /api/user/profile`
  - `GET /api/user/page`（ADMIN）
  - `GET /api/user/{id}`（ADMIN）
- 分页支持 `keyword`（昵称/账号/手机号）、`role`、`status` 筛选

### 第 6 步：登录模块

- `POST /api/auth/login`：用户名 + 密码 → BCrypt 校验 → JWT
  - 账号不存在和密码错误返回同一句「账号或密码错误」
  - 状态为 0 的账号返回「已被禁用」
- `POST /api/auth/wx-login`：`code` → 调微信 `jscode2session` → 拿 openid → 首次登录自动建档（OWNER）
  - 未配置 AppID/Secret 时返回明确提示，阶段 3 填配置后可用

### 第 7 步：演示账号

`DataInitializer` 在首次启动且 `sys_user` 为空时创建：

| 账号 | 密码 | 角色 |
|---|---|---|
| admin | admin123 | ADMIN |
| staff001 | staff123 | STAFF |
| owner001 | owner123 | OWNER |

用 BCrypt 现场加密，不往 SQL 里手写哈希。

### 第 8 步：数据库脚本

`backend/src/main/resources/db/init.sql`：

1. 创建数据库 `car_beauty`（utf8mb4）
2. 创建应用账号 `beauty / Beauty@2026` 并授权
3. 创建 12 张表：
   `sys_user`、`car`、`service_type`、`service_order`、`service_process`、`points_goods`、`points_exchange`、`points_record`、`message`、`notice`、`activity`、`activity_signup`
4. 插入 4 条演示服务项目

```

```

### 第 9 步：服务项目模块（2026-11-19 补充）

对应七大模块中的「美容订单类型管理」。

- `ServiceType` 对应 `service_type` 表，继承 MyBatis-Plus 的分页查询能力
- 接口：
  - `GET /api/service-type/page`：管理端分页，支持 name / category / status 筛选（ADMIN）
  - `GET /api/service-type/list`：车主端只看 `status=1` 的上架项目
  - `GET /api/service-type/{id}`：详情
  - `POST` / `PUT` / `DELETE`：新增、修改、逻辑删除（ADMIN）
  - `PUT /{id}/status?status=1`：上下架（ADMIN）
- 删除采用逻辑删除，历史订单里引用的项目不会消失
- `ServiceTypeSaveDTO` 用 Jakarta Validation 校验名称、价格、时长等必填项

### 第 10 步：Swagger 接口文档（2026-11-19 补充）

- 引入 `springdoc-openapi-starter-webmvc-ui 2.8.17`（2.x 才对应 Spring Boot 3）
- `OpenApiConfig` 注册文档标题、说明和 `BearerAuth` 安全方案
- 控制器加 `@Tag` / `@Operation` 中文说明；需要登录的控制器加 `@SecurityRequirement`
- 启动后访问 <http://localhost:8081/swagger-ui.html>，点 Authorize 粘贴登录返回的 token 即可调试
- 拦截器只拦 `/api/**`，Swagger 自己的静态资源不受影响，无需额外放行

## 七、踩过的坑

| 问题 | 原因 / 解决 |
|---|---|
| 8080 启动失败 | 本机 Jenkins（java 进程 PID 6700）占用 8080；后端改为 8081 |
| `mvn` 命令不存在 | 本机未单独装 Maven；用 IDEA 自带 Maven 构建，并生成 Wrapper |
| 依赖下载慢/首次编译久 | 首次从 Maven Central 拉取，属正常；之后走本地仓库 |
| MyBatis-Plus 分页不生效 | 3.5.9+ 需要额外依赖 `mybatis-plus-jsqlparser`，已加 |
| 403 时 ThreadLocal 可能泄漏 | 调整顺序：角色校验通过后再 `UserContext.set` |
| CORS 预检被拦截 | 拦截器放行 `OPTIONS` 请求 |
| IDEA 不认 Maven 项目 | 根目录 `.idea/modules.xml` 未注册 backend；需右键 `backend/pom.xml` → Add as Maven Project |
| IDEA 项目 SDK 是 25 | `.idea/misc.xml` 用 JDK 25；需改为 17 并设 language level 17 |
| MySQL root 密码未知 | 建库脚本由本人执行；应用使用专用账号 beauty，不保存 root 密码 |
| Redis 未启动 | 阶段 2 不依赖 Redis；依赖已引入，等后续需要缓存/登录态时再启动服务 |
