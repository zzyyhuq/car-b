# 第 6 周（2026-11-23 起）积分管理与管理端补全

> 对应路线图：阶段 4（铺模块 + Vue 管理端）。
> 验收标准：车主兑换后，门店能在管理端查到兑换单并完成核销；管理员能维护积分商品。

## 一、本周目标

1. 积分商品管理：分页、新增、编辑、删除、上下架
2. 兑换单管理：分页、单号/状态筛选、到店核销
3. 权限：商品管理仅 ADMIN；兑换查询和核销 ADMIN + STAFF
4. 管理端页面与后端接口联调

## 二、完成内容

### 1. 后端积分管理接口（2026-11-23）

- `GET /api/points/goods/page`：管理端商品分页，支持 name / status 筛选
- `POST /api/points/goods`、`PUT /api/points/goods/{id}`：新增、修改商品
- `PUT /api/points/goods/{id}/status?status=1`：上架/下架
- `DELETE /api/points/goods/{id}`：逻辑删除，商品不再展示
- `GET /api/points/exchange/page`：兑换单分页，支持 exchangeNo / status / userId / goodsId
- `PUT /api/points/exchange/{id}/verify`：核销，`PENDING → VERIFIED`，写 `verify_time`
- `PointsExchangeVO` 增加 `userName`，管理端列表直接显示车主昵称
- 核销不改积分和库存：兑换时已经扣过，核销只是线下交付确认

### 2. 管理端页面

- 新增「积分商品」页：分页、名称/状态筛选、新增、编辑、上下架、删除
- 新增「兑换核销」页：兑换单分页、状态筛选、核销按钮
- 侧边栏：
  - 积分商品仅管理员可见
  - 兑换核销管理员和员工都可见
- 路由守卫：员工直接访问 `/points/goods` 会跳回订单页

## 五、设计决定

- **核销不改积分/库存**：兑换时已经在同一事务里扣过积分和库存，核销只代表车主到店领到了商品，避免重复扣减。
- **商品管理只给管理员，核销给员工**：符合需求里的权限矩阵——管理员维护商品，门店员工负责到店核销。
- **商品逻辑删除**：兑换单记录保留，商品不再出现在小程序商城；如果后续需要历史兑换单显示原商品名，可增加商品名称快照字段。
- **兑换单状态**：`PENDING 待核销 / VERIFIED 已核销 / CANCELLED 已取消`，当前只实现核销，取消留作后续扩展。
